**Step 1: MessageViewer Livewire component (VIEW-01 through VIEW-04, D-09, D-10)**

Create `app/Livewire/Mailbox/MessageViewer.php`:
- Properties: `$folderPath` (string), `$uid` (int), `$message` (nullable Message object), `$sanitizedHtml` (nullable string), `$textBody` (nullable string), `$showImages` (bool, default false)
- Mount method: receives `$folderPath` and `$uid` from route parameter
- Method `loadMessage()`: calls `ImapMailboxService::getMessage($this->folderPath, $this->uid)`, stores in `$this->message`. If message has HTML body, runs through `MessageSanitizer::sanitizeHtml()` (server-side, D-10) and stores in `$this->sanitizedHtml`. If plain text only, stores in `$this->textBody`.
- Method `toggleImages()`: flips `$this->showImages`. If true, re-runs sanitizer without image blocking.
- Method `getFromDisplay()`: returns `$this->message->from_name ?? $this->message->from_address`
- Method `getToDisplay()`: returns formatted To/Cc/Bcc from message headers
- Render: returns `livewire.mailbox.message-viewer` view with message data, sanitized HTML, text body, and attachment list.
- On mount: automatically mark as read via `ImapMailboxService::setFlag($folderPath, [$uid], '\Seen', true)` (VIEW-05).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IMAP Server → Laravel Backend | Email content (HTML, headers, attachments) arrives from external mail server — untrusted |
| Laravel Backend → Browser | Sanitized email content, attachment downloads cross here |
| Browser → Laravel Backend | User actions (delete, move, bulk operations) cross here — must validate against IMAP state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Tampering | Email HTML rendering | critical | mitigate | Dual sanitization: HTMLPurifier strips scripts/events/dangerous URLs server-side, DOMPurify runs client-side at render time. Sandboxed iframe with empty sandbox="" prevents escaped content from accessing parent page. Remote images blocked by default (D-11). |
| T-02-07 | Tampering | Attachment downloads | high | mitigate | UUID-based filenames prevent path traversal (SEC-08). MIME type validation blocks executables (SEC-09). Streams directly from IMAP — no local file storage means no filesystem attack surface (D-12). |
| T-02-08 | Information Disclosure | Remote image tracking | medium | mitigate | D-11 blocks remote images by default. `<img src>` rewritten to `data-src`. User must explicitly click "Display images" per message. No automatic loading of external resources. |
| T-02-09 | Tampering | Bulk operations | medium | mitigate | D-17 uses IMAP STORE/COPY with UID sets. UIDs validated against current folder. Operations are atomic per IMAP specification. User can only operate on their own mailbox (session-scoped credentials). |
| T-02-10 | Spoofing | Message display | low | accept | Email headers (From, Subject) are displayed as-is from IMAP. Spoofed headers are an email protocol issue, not an application vulnerability. Display only — no trust implied. |
| T-02-SC | Tampering | npm installs | high | mitigate | DOMPurify installed via npm. Verified via Package Legitimacy Audit: 17.4k GitHub stars, OpenSSF Best Practices certified. No [SLOP] or [SUS] packages. |
</threat_model>
