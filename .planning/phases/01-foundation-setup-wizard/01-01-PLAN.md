    Wire ONE end-to-end path: fresh install → install lock middleware detects no lock → redirects to /install → wizard shell renders → login page renders. This is the thinnest vertical slice touching every layer.

    **Step 1: Scaffold Laravel 12 project.** Run `composer create-project laravel/laravel openmail` in the project root (or if already initialized, ensure composer.json has laravel/framework ^12.0). Then `composer require livewire/livewire webklex/laravel-imap ezyang/htmlpurifier spatie/laravel-csp`. Then `npm install && npm run build` for Tailwind v4 + Vite.

    **Step 2: Create database migrations.** Three migrations:
    - `0001_01_01_000000_create_users_table.php`: id, name, email (unique), password (nullable — IMAP auth doesn't store local password), remember_token, timestamps. Must implement `Illuminate\Contracts\Auth\Authenticatable`.
    - `0001_01_01_000001_create_sessions_table.php`: id (unsignedBigInteger), user_id (nullable, foreign key), ip_address (nullable), user_agent (text), payload (longText), last_activity (integer). Index on last_activity. Per D-02 + DB-02: SESSION_DRIVER=database.
    - `0001_01_01_000002_create_settings_table.php`: id, key (string, unique index), value (longText nullable), group (string, default 'general'), timestamps. Per DB-05.

    **Step 3: Create models.** User model (implements Authenticatable, fillable name/email, hidden password). Setting model (key/value/group fillable, with static `get($key, $default)` and `set($key, $value)` helpers, use Cache::remember for reads).

    **Step 4: Create InstallLock middleware.** Per research Pattern 2: check `storage_path('installed')`. If request path starts with `/install` AND lock file exists → abort 404. If request path does NOT start with `/install` AND lock file does NOT exist → redirect to `/install`. Register in Kernel.php route middleware.

    **Step 5: Create InstallLock route and controllers.** Route GET `/install` → SetupController@show (wizard shell). Route GET `/login` → LoginController@show (login page). All other routes protected by InstallLock middleware.

    **Step 6: Create setup wizard shell.** Minimal Livewire component `SetupWizard` with `$currentStep = 1` and `$totalSteps = 8`. Blade view renders step indicator (1-8 with current highlighted) and placeholder content per step. No form logic yet — just the navigation shell.

    **Step 7: Create login stub.** Livewire `LoginForm` component with email + password fields (wire:model deferred, NOT wire:model.live per anti-pattern). Blade view with form styling via Tailwind. No IMAP auth yet — just the UI shell.

    **Step 8: Create services.** MailConfigDetector with domain → provider mapping (Gmail, Outlook/365, Yahoo + generic fallback per D-09/D-10/D-11). SystemRequirementsChecker with PHP version check (>=8.2), required extensions check (mbstring, openssl, pdo, pdo_mysql, curl, xml, tokenizer), directory permissions check (storage, bootstrap/cache writable), database driver check. Both services are pure PHP, testable in isolation.

    **Step 9: Configure auth and session.** config/auth.php: add 'imap' guard (driver: session, provider: users). config/session.php: driver=database, lifetime=1440 (24h per D-13), http_only=true, same_site=lax (per D-15), secure=env('SESSION_SECURE_COOKIE'). config/openmail.php: mail config defaults (imap_host, imap_port=993, imap_encryption=ssl, smtp_host, smtp_port=465, smtp_encryption=ssl per D-12).

    **Step 10: Configure .env.** Set APP_NAME=OpenMail, DB_CONNECTION=sqlite (for local dev), SESSION_DRIVER=database, CACHE_STORE=database. Create storage/installed as empty file (for testing lock behavior). Verify app boots: `php artisan serve` starts without error.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Laravel | HTTP requests to /install, /login, and API routes. CSRF protection required. |
| Laravel → Database | MySQL/MariaDB connection for sessions, settings, users. Credentials in .env. |
| Laravel → IMAP Server | Future: connection for authentication. Must use TLS. |
| .env File | Contains database credentials, APP_KEY. Must not be web-accessible. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | /install route | high | mitigate | InstallLock middleware blocks access when lock file exists (SETUP-10) |
| T-01-02 | Information Disclosure | .env file | high | mitigate | .env in .gitignore; APP_KEY generated on install; file permissions 644 |
| T-01-03 | Elevation of Privilege | Install bypass | high | mitigate | Lock file checked on every request; race condition handled via flock in Plan 02 |
| T-01-04 | Tampering | CSRF on forms | medium | mitigate | @csrf directive on all Blade forms; VerifyCsrfToken middleware (AUTH-05) |
| T-01-05 | Information Disclosure | Session data | medium | mitigate | SESSION_DRIVER=database; HttpOnly cookies; SameSite=Lax (D-15) |
| T-01-06 | Tampering | Database credentials | medium | mitigate | Credentials only in .env; never logged; never stored in DB |
| T-01-07 | Denial of Service | Large .env writes | low | accept | Single-server deployment; no rate limiting needed for setup wizard |
</threat_model>
