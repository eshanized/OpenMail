<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User Label Actions → Backend | Create/edit/delete labels, apply/remove from messages; validated server-side |
| Archive Action → IMAP Server | IMAP MOVE command to Archive folder; folder path from FolderMapper heuristic |
| Label Filter → Message List | Label ID from URL/click; verified owned by user before filtering |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-16 | Tampering | Label apply/remove cross-user | medium | mitigate | LabelService scopes all operations to authenticated user_id; pivot table has user_id via message_metadata |
| T-04-17 | DoS | Archive moves large selection | low | mitigate | Bulk archive uses IMAP UID SET (single command); limit selection to 100 messages |
| T-04-18 | Info Disclosure | Label counts cross-folder | low | mitigate | LabelService.getForUser() counts only user's messages; no cross-folder leakage |
| T-04-19 | Spoofing | Fake Archive folder creation | low | accept | FolderMapper heuristic for \Archive SPECIAL-USE; user can configure in settings later |
| T-04-20 | Repudiation | Archive undo not audited | low | accept | Phase 5 adds audit logging; v1 accepts no audit for undo |
</threat_model>
