<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → Settings UI | Authenticated user modifies own profile, preferences, sessions |
| User → Composer | Authenticated user composes emails with signature insertion |
| Browser → Session Revoke | User revokes own other sessions via Security tab |
| Signature Content → Renderer | User-created signature HTML rendered in composer/emails |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-22 | Elevation of Privilege | Session revocation bypass | medium | mitigate | SecurityTab only shows sessions for auth()->id(); revoke deletes by session ID with user_id check |
| T-05-23 | Information Disclosure | Session list exposes other users | low | mitigate | Sessions query filtered by user_id; no cross-user access |
| T-05-24 | Tampering | Mail preference injection | low | mitigate | SettingsRequest validates enums for page_size/default_folder/reply_behavior; Setting::setForUser() scopes to user |
| T-05-25 | Tampering | Profile email takeover | medium | mitigate | Email uniqueness validated; current password not required for email change (v1) — documented limitation |
| T-05-26 | Tampering | Signature swap in composer | low | accept | User controls own signatures; dropdown only shows own signatures |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | Package legitimacy audit completed; all packages [OK] |

</threat_model>
