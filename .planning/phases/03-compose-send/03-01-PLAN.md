**Step 4 — ComposerService (per D-17, D-18, Pattern 3):**

Create `app/Services/ComposerService.php`:

Constructor: inject `ImapMailboxService`, `MessageSanitizer`

`buildMimeMessage(array $data, ?string $userId = null): \Symfony\Component\Mime\Email`:
- Create `Symfony\Component\Mime\Email` instance
- Set from: authenticated user's email and name
- Set to, cc, bcc from `$data` (parse comma-separated into Address objects)
- Set subject
- Set text body: convert HTML to plain text via `strip_tags()`, `html_entity_decode()`, `wordwrap()`
- Set html body: `$data['body']`
- Attach files from `$data['attachments']` array (path, original name, MIME type) using `DataPart::fromPath()`
- Generate Message-ID: `<uuid@app.domain>`
- For replies/forwards: set In-Reply-To and References headers from `$data['in_reply_to']` and `$data['references']`

`sendMessage(int $userId, array $data): array`:
- Build MIME message via `buildMimeMessage($data, $userId)`
- IMAP APPEND to Sent folder FIRST (per D-17): `$this->imapService->appendToSent($mimeMessage->toString())`
- On APPEND failure: throw exception, do not proceed to SMTP
- Send via SMTP: Use `Illuminate\Support\Facades\Mail::raw()` with the raw MIME string. Set To/Cc/Bcc/Subject on the Mail message. Use `$message->using()` callback to replace Symfony's generated MIME with our pre-built one. Specifically, access the Symfony Email object via the `using` callback and copy headers/body from our built MIME message.
- On SMTP success: return `['success' => true, 'sent_uid' => $sentUid]`
- On SMTP failure (per D-18): Create PendingSend record with status 'pending', send_at = now() + configured delay, message_json = composer data, mime_message = raw MIME string, sent_folder_uid = the UID from IMAP APPEND. Return `['success' => false, 'queued' => true]`

`saveDraft(int $userId, array $data, ?string $existingDraftUid = null): array`:
- Build MIME message
- IMAP APPEND to Drafts folder: `$this->imapService->appendToDrafts($mimeMessage->toString(), $existingDraftUid)`
- Return `['success' => true, 'draft_uid' => $uid]`

`undoSend(int $pendingSendId, int $userId): bool`:
- Find PendingSend by ID and user_id, verify status is 'pending'
- Update status to 'cancelled'
- If sent_folder_uid exists, delete from Sent folder via ImapMailboxService
- IMAP APPEND to Drafts folder with the mime_message (move to Drafts per D-24)
- Return true

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Composer Modal | User input crosses from untrusted browser to server via Livewire — To/CC/BCC fields, subject, body, attachments |
| ComposerService → SMTP | Pre-built MIME message crosses to external SMTP server — must not leak credentials or internal data |
| ComposerService → IMAP | IMAP APPEND operations cross to mail server — must use authenticated connection, correct folder paths |
| PendingSend → Scheduler | Database queue crosses from web request to background scheduler — must scope to user, validate status transitions |
| Attachment Upload → Temp Storage | File upload crosses from browser to server filesystem — must validate size, MIME type, prevent path traversal |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | ComposerService::sendMessage | high | mitigate | Use authenticated user's email as From address; never allow user to set arbitrary From via composer form |
| T-03-02 | Tampering | MIME message construction | high | mitigate | Use Symfony\Component\Mime\Email for RFC-compliant MIME building; do not concatenate raw strings |
| T-03-03 | Repudiation | Send/draft actions | low | accept | Logging send actions deferred to Phase 5 (SEC-05 audit logging) |
